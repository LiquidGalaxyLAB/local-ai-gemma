# KML Icon Deployment & Rendering Verification

Earth 7.3.3 on VirtualBox silently drops placemarks that reference missing icons. The icon URL is fetched asynchronously — if it returns 404, the entire placemark may not render.

## Icon Inventory (deployed to lg1:81/kml/icons/)

Generated by `/home/nara/wm-collector/generate_icons.py` (16 icons, 48x48px RGBA PNGs):

- `plane.png` — Air traffic
- `earthquake.png` — Earthquake events
- `military.png` — Military bases/shield
- `news.png` — News articles
- `wildfire.png` — Flame shape
- `storm.png` — Cyclone spiral
- `flood.png` — Water drop
- `alert.png` — Exclamation triangle
- `circle-{color}.png` — Generic dots (red, blue, green, yellow, orange, white, cyan, purple)

## Verification Steps

After deploying a KML that references custom icons:

```bash
# 1. Check each icon used in the KML returns 200
curl -s -o /dev/null -w "%{http_code}" http://lg1:81/kml/icons/plane.png

# 2. Check Earth is actually requesting the icons
sudo grep "plane.png" /var/log/apache2/other_vhosts_access.log | grep GoogleEarth
# If 0 requests: Earth's NetworkLink subsystem may be broken (see kml-not-visible-diagnosis.md)

# 3. Fallback: Use Google CDN icons when local icons don't work
# http://maps.google.com/mapfiles/kml/paddle/red-circle.png
# http://maps.google.com/mapfiles/kml/shapes/placemark_circle.png
```

## Common Failures

| Symptom | Cause | Fix |
|---------|-------|-----|
| Placemarks don't render, KML HTTP 200, Earth fetches KML | Icon URL returns 404 | Generate and deploy icons via generate_icons.py, sudo cp to /var/www/html/kml/icons/ |
| Earth makes zero icon requests | NetworkLink subsystem broken | Check Earth was launched with --no_system_check --no_signin |
